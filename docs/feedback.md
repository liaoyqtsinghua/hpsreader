# HPS Reader 使用反馈记录

本文档用于记录实际使用过程中发现的问题、需求和体验阻塞，后续统一评估优先级并转入开发任务。

## 待处理反馈

### F-001 批量生成翻译能力不足

- 提出时间：2026-05-07
- 类型：功能需求
- 优先级：高
- 状态：基础修复已完成

当前希望支持批量生成翻译，并提供更细的范围控制：

- 全部生成。
- 生成固定页数。
- 可选择起始页。

初步处理方向：

- 在 Workbench 或 Marginalia 增加“批量翻译”入口。
- 批量任务应支持范围参数：全文、页码范围、起始页 + 页数、当前文档剩余部分。
- 后端需要增加批量任务队列，避免一次性请求过大。
- 每个段落/页的翻译结果应逐步保存，并记录 Agent event。
- 2026-05-07 复测反馈：当前实现仍未满足实际使用中的“批量生成译文”预期，需要重新检查入口可见性、任务范围、执行状态和结果写回。
- 2026-05-07 处理记录：已改为后端任务式批量翻译接口，支持全部未译段落、起始页 + 页数、从当前段落到文档末尾、仅处理未译段落开关；前端按 job 轮询进度，后端逐段保存译文并记录认知足迹。后续如需长队列/暂停/恢复，可继续扩展为持久化任务队列。

### F-002 LLM 翻译结果未显示

- 提出时间：2026-05-07
- 类型：缺陷
- 优先级：高
- 状态：基础修复已完成

前端显示可以调用 LLM 进行翻译，但调用后无法显示翻译结果。

需要排查：

- 前端是否正确接收 `/api/llm/chat` 返回的 `text` 字段。
- DeepSeek/OpenAI-compatible 返回格式是否与当前解析逻辑一致。
- `translateSegmentWithLlm` 是否将结果写入当前段落 textarea。
- `saveSegment` 后 `refreshProject` 是否覆盖了前端临时状态。
- 后端错误是否只显示 toast，而没有在 UI 中留下可追踪信息。

初步处理方向：

- 为 LLM 调用增加可见的 loading / success / error 状态。
- 在 Agent event 中记录 provider、model、segmentId、错误信息或输出摘要。
- 在前端保留最近一次 LLM 原始返回摘要，便于排查。
- 增加一个最小测试按钮，用于验证当前 Provider 是否能返回文本。

### F-003 OCR 后丢失原文图片上下文

- 提出时间：2026-05-07
- 类型：功能缺口 / 文档摄取体验
- 优先级：高
- 状态：基础修复已完成

OCR 识别之后，目前阅读器主要保留提取出的文本段落，原文版面和页面图片上下文容易丢失。对于学术文献、古籍、图表、脚注、边注和复杂排版来说，这会影响校对和理解。

期望方向：

- OCR 后保留每页原始图片或 PDF 页面截图。
- 在原文段落旁提供“查看原图”入口，点击后显示对应页图像。
- 支持原文图片弹窗、侧边预览或独立窗口查看。
- 段落数据中记录来源页码、页面坐标、OCR 置信度。
- 对复杂页面可调用多模态模型，让模型基于页面图片进行解释、校对或结构化识别。

初步处理方案：

- 摄取阶段生成 `page_images` 或 `page_snapshots`。
- 新增数据结构：`pages[]`，包含 `pageIndex`、`imagePath`、`width`、`height`、`ocrStatus`。
- `segments[]` 增加 `pageIndex` 和可选 `bbox`。
- 前端在段落工具栏加入“原图”按钮。
- 后续可增加“多模态处理”入口：把当前页图片发送给支持视觉能力的模型。
- 2026-05-07 Sprint B 处理记录：新增右侧“原文页图”面板，PDF 文档可用浏览器 PDF.js 渲染当前页，保留原始版面用于校读；原文件仍可在预览窗口中查看并下载。当前无原生服务端 PDF 渲染依赖，因此暂未把每页截图持久化为 `page_images` 文件，后续可扩展为浏览器页图上传或服务端渲染插件。

### F-004 Agent 需要中文译名，并增加语言学习 Agent

- 提出时间：2026-05-07
- 类型：Agent 体验 / 新 Agent 需求
- 优先级：中高
- 状态：部分处理

当前 Agent 名称偏英文，不适合中文用户直接理解。需要为所有 Agent 增加中文译名，并新增一个面向“学习文档原语言”的 Agent。

命名方向：

- `Scholarly Workshop`：研习工坊 Agent
- `Terminology Sentinel`：术语一致性哨兵
- `Academic Translator`：学术翻译 Agent
- `Conceptual Archeology`：概念考古 Agent
- 新增：原语言学习 Agent

“原语言学习 Agent”思路：

- 目标是帮助用户学习文档的原语言，而不是只给译文。
- 根据当前段落解释语法、词形、句法结构和关键词。
- 提供逐句拆解、核心词汇表、例句、记忆提示。
- 支持按用户水平调整解释深度：入门、中级、研究级。
- 可结合术语库，追踪同一词在全文中的不同用法。

初步处理方向：

- 在 `skills.js` 中增加中文 `labelZh` 或直接改为中文 UI 名称。
- 新增 `source-language-tutor` Skill。
- 前端 Agent 下拉显示中文名，保留英文 id 作为内部标识。
- 2026-05-07 Sprint C 处理记录：Agent Skill 已使用中文名称展示；`source-language-tutor` 原语言学习 Agent 已可选；前端会同时显示当前 Provider 的 Agent 可用性。

初步处理方向：

- Agent 面板增加模板选择器。

### F-007 OCR 乱码、字体适配与开源 OCR 方案确认

- 提出时间：2026-05-07
- 类型：OCR 缺陷 / 技术路线确认
- 优先级：高
- 状态：基础修复已完成

OCR 识别之后存在乱码问题，需要考虑字体适配、字符集处理和 OCR 技术路线。同时需要明确当前 OCR 是否已经调用开源方案。

当前状态说明：

- 当前程序对 PDF 主要使用 `pdf-parse` 提取 PDF 内嵌文本。
- 这不是完整 OCR，只适用于带文本层的 PDF。
- 扫描版 PDF / 图片目前进入 `pending-ocr` 状态，尚未真正调用 PaddleOCR、Tesseract 等开源 OCR。

可能原因：

- PDF 内嵌字体编码异常，导致 `pdf-parse` 提取后出现乱码。
- 文献包含特殊字符、希腊文、法文重音、学术符号或古典语言字符。
- PDF 文本层本身质量较差。
- 缺少字体映射、Unicode normalization 和后处理规则。

初步处理方向：

- 增加 OCR Provider 层，优先接入 PaddleOCR 或 Tesseract。
- 对 PDF 文本提取增加乱码检测，乱码严重时自动转为页面图像 OCR。
- 增加字符规范化：Unicode NFC/NFKC、连字修复、断词修复、重音字符保留。
- 增加字体/语言适配策略：拉丁文、希腊文、法文、德文、中文分别处理。
- 在文档详情中显示当前摄取方式：PDF text layer / OCR / 手动导入。
- 2026-05-07 Sprint B 处理记录：已接入 `tesseract.js` 作为本地开源 OCR Provider，新增 `/api/ocr/providers`、文档 OCR 状态接口和 OCR 写回接口；图片文件可直接 OCR 并重建段落。PDF 当前由前端 PDF.js 渲染当前页图，再把页图传给后端 Tesseract.js OCR，以避免 Windows 原生渲染依赖。新增 OCR 文本规范化和乱码检测状态，后续可接入 PaddleOCR/Tesseract CLI 做更强的批量页图 OCR。

### F-013 术语修正失效，且未考虑词形变化

- 提出时间：2026-05-07
- 类型：术语系统缺陷
- 优先级：高
- 状态：基础修复已完成

当前术语修正功能失效，同时术语匹配没有考虑词形变化。对于拉丁文、希腊文、法文、德文、英文等文献，术语可能出现复数、变格、变位、阴阳性、大小写、重音、连字符等变化，简单字符串匹配无法满足学术阅读需求。

问题表现：

- 点击术语修正后没有产生预期修改。
- 已确认术语无法覆盖常见词形变化。
- 术语一致性监视可能漏报或误报。

期望方向：

- 术语库支持一个概念对应多个词形。
- 支持大小写不敏感、重音规范化、连字符/空格变化。
- 支持用户手动添加变体。
- 后续可接入 lemmatizer / stemmer / morphological analyzer。
- 术语修正应明确显示将如何修改译文，避免盲目追加词语。

初步处理方向：

- 术语数据结构增加 `variants[]`、`lemma`、`language`。
- 匹配时使用 normalized form，而非简单 `includes`。
- 术语修正从“追加译法”改为“提出替换建议 / 用户确认”。
- 对当前段落显示命中的词形和来源术语。
- 2026-05-07 处理记录：术语数据结构已增加 `variants[]`、`lemma`、`language`；术语高亮和一致性扫描改为统一匹配器，支持大小写不敏感、重音弱匹配、连字符/空格变化和简单复数变体；术语修正会弹出可编辑确认，不再静默追加译法。后续仍可接入真正的 lemmatizer / morphological analyzer。

- 提出时间：2026-05-07

- 优先级：高

当前无法在已经生成好的译文或原文中直接进行 comment。实际使用中，用户需要选中原文或译文的一段文字，添加批注、问题、校勘意见或研究笔记，并且在写 comment 时可以调用 LLM 辅助。
